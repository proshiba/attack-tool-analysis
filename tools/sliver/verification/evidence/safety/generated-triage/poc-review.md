## Human review

These are stripped, statically linked x86-64 Linux implants generated by the
reviewed Sliver v1.7.3 server: a 10+0-3 second HTTP beacon, a 10+0-3 second
HTTPS beacon, and an interactive raw-mTLS session implant. VM 105 independently
fetched them from the contained Kali staging listener, verified each hash, and
checked the ELF type and architecture with `file` and `readelf`.

The generated configurations contained only Kali VM 100 at
`192.168.1.50:8080`, `192.168.1.50:8443`, or `192.168.1.50:31337`. No DNS,
proxy, fallback, canary, public hostname, or alternate C2 was configured. The
mechanical scanner's apparent public IP strings were concatenated X.509 OID
bytes, not configured endpoints; source review accounted for the actual
transport destinations. HTTP downgrade/fallback was disabled for HTTPS, the
cleartext build was forced to HTTP, and Kali's execution-window firewall
permitted only loopback and `192.168.1.0/24`.

**Verdict: `safe-to-run-in-lab` under the documented scope and runtime
controls.** Execution was limited to Kali VM 100 for generation/operator work
and Ubuntu VM 103 for the implants. VM 103 was restored to
`linux_verify_baseline` before execution and rolled back after all three
collections with Proxmox task exit status `OK`; post-rollback checks found no
run directories, implant paths, marker, or implant process and confirmed
Sysmon, auditd, and qemu-guest-agent active.
